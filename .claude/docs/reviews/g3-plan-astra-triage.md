# G3: Astra's review of the plan, triaged

`Tools/Agent/astra.sh -e high`, 2026-10-25. Astra ran the Node pilot (20 of 20, the G2 baseline) and in-memory
Trainer probes of profit-only plans at +1, +3 and +7 (20 of 20 each, stopping at different episode counts from +10)
and of the plans the plan calls indifferent (dogs served only: the cap on seed 1, stable at 79,000 and 68,500 on
seeds 2 and 3). Twelve findings; eleven accepted, one accepted in part.

| # | Finding (short) | Verdict | What changed |
|---|---|---|---|
| 1 | High: an editable Profit slider in Round 1 contradicts section 8 ("students only predict") | **Accepted** | Round 1 is locked entirely: `planLocked(preset)` (a preset that uses its whole allowance) disables every toggle and slider; `#limit` reads "Round 1: the plan is set. Predict what the GM will do, then train." The round selector is what lets the owner edit without instructions (D35). |
| 2 | High: the words name only the positive direction of profit and reputation; a drop or a loss counts the opposite | **Accepted in part** | The sentence keeps the bible's template character for character. A hint line under it (`signedNote(spec)`, `#plan-note`) says profit and reputation count both ways, sign-neutral so it stays true under a negative weight; shown whenever either is on with a non-zero weight; its own tests. |
| 3 | High: the edited-plan e2e could pass while Train still used Round 1 | **Accepted** | The e2e waits for the run to end, then compares `#readout` to `describeWeek` of a node-side Trainer run of the same edited spec and seed (and checks that sentence differs from Round 1's); the prediction's exact value is asserted. |
| 4 | Medium: results of a previous run stay beside a changed plan | **Accepted** | Any edit or round change after a run clears the readout, the status and the curve; the status says "The plan changed. Train the GM to see what it does with this one." The spec is snapshotted at the click. The e2e checks it. |
| 5 | Medium: the control-locking lifecycle and the pilot's synchronisation were unspecified | **Accepted** | Every control (editor, selector, prediction, seed, Fast, Train) is disabled during training and the whole pilot and restored in `finally`, the editor to its round's own locks; the pilot loads Round 1 into the editor, words and spec together and says "Round 1" in its heading; e2e on `?pilot=1&round=3`. |
| 6 | Medium: a measure on at weight 0 hides an exact Round 1 equivalent | **Accepted** | `targetOutcome` treats a measure on at 0 as off: Profit positive and everything else off or 0 is the Round 1 plan; tests added. The editor's limit still counts it as on. |
| 7 | Medium: positive scaling preserves the objective, not the exact trajectory | **Accepted** | The plan and the doc comment say so; the target classification stays. |
| 8 | Medium: "never settles" stated as universal; the promised numbers were missing | **Accepted** | "May exhaust the budget"; the result section records specs, seeds, commands and outcomes via the harness's `--reward`; "last test week" is the fresh greedy evaluation `app.ts` already makes at the end, labelled "still changing its mind" when the run ends without stable. |
| 9 | Medium: constant predicates do not test the six-week contract | **Accepted** | The test records what the predicate is asked: the fixed week first, then weeks 1..5, six calls on the first stable evaluation; a predicate refusing the fourth call gives target not met with stopping unchanged; a predicate accepting a non-Round-1 week on the balanced plan is met. |
| 10 | Medium: the plan's test wording had the legal ratio changing the KPI name | **Accepted** | The name "Blocks over the legal ratio" carries no number; the test pins all six names and unit hints and changes only the fatigue name (threshold) and the clauses (ratio, threshold) with the config. |
| 11 | Medium: the harness tests missed the failure paths | **Accepted** | Tests for a plan read from a JSON file (same row as the preset), an invalid file and a malformed file (exit 2), `--reward` with no value (exit 2), and a targetless run that ends before stability (exit 1, "0 of 1 seeds stable within budget"). |
| 12 | Low: the e2e budget is neither measured nor enforced; the deadline wording cannot be reached in a run | **Accepted** | The budget is the tests' own time as Playwright reports it (the build and server start are outside it), measured in the result; `statusText` is unit-tested for the three endings (stable; stopped at the episode limit; 60 s is up), so the deadline wording needs no 60 s browser run. |
